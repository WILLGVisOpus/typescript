# Task 2.3 — HMAC-signed backend client (Issue #206 / Phase 2)

**Date:** 2026-04-29
**Branch:** `feat/206-zitadel-soft-mfa-fork`
**Issue:** [#206 — Soft-required MFA umbrella](https://github.com/WILLGVisOpus/VisOpus-Test/issues/206)
**Plan:** Task 2.3

## Goal

The fork's Phase 3 pages (skip-warning, recovery-codes-set,
recovery-code-challenge, full-reset/{initiate,complete}) need to call
the Phase 1 backend endpoints we just landed. This module is the only
place in the fork that knows how to sign such requests; pages call its
typed methods.

## What landed

### `src/lib/server/visopus-backend.ts`

- `sign(body)` — private helper. Produces `(ts, sig)` matching the
  backend's `_verify_mfa_recovery_signature`:
  `HMAC-SHA256(secret, "<ts>." + sha256(body))`.
- `post<T>(path, body)` — private helper. Refuses to fire if either
  `MFA_RECOVERY_HMAC_SECRET` or `BACKEND_INTERNAL_API_URL` is unset
  (fail-fast on misconfiguration). Throws `Error("backend <status>: <body>")`
  on any non-2xx — caller decides whether to translate.
- Six typed wrappers: `skip`, `verifyRecoveryCode`,
  `regenerateRecoveryCodes`, `initiateFullReset`, `completeFullReset`,
  `auditLog`.
- Default arg `context: "challenge"` on `verifyRecoveryCode` and
  `trigger: "user_request"` on `regenerateRecoveryCodes` matches the
  intended call pattern from the Phase 3 challenge / regenerate pages.

### `src/lib/server/visopus-backend.test.ts`

10 vitest cases (all green):

- `skip` builds the correct URL, body, and HMAC signature (cross-checked
  against an in-test re-implementation of the algorithm).
- `verifyRecoveryCode` defaults `context` to `"challenge"`.
- `verifyRecoveryCode` forwards an explicit context.
- `regenerateRecoveryCodes` defaults `trigger` to `"user_request"` and
  parses the `codes` response.
- `initiateFullReset` POSTs `{email}` to the right path.
- `completeFullReset` POSTs `{token, code}` and returns `login_url`.
- `auditLog` POSTs `{user_id, event, metadata}`.
- Non-2xx response → `Error` with status code in message.
- Missing `MFA_RECOVERY_HMAC_SECRET` → throws before fetch (no leak via
  unsigned request).
- Missing `BACKEND_INTERNAL_API_URL` → throws before fetch.

## Plan deviation

- Plan suggested `"use server"` directive. Dropped it — these are async
  utility functions, called from server actions in Phase 3 pages. The
  Next.js boundary lives in those pages, not here. Keeping it as a plain
  module avoids the constraint that every export must be an async
  function (which is already true here, but adding the directive
  lock-ins serializability constraints we don't need on internal types).
- Added explicit response type aliases (`SkipResponse`, `VerifyRecoveryResponse`,
  …) so the Phase 3 pages get auto-complete on response shapes.
- Fail-fast on missing env vars — silent unsigned requests would be a
  security footgun in production.
